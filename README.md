# VANILLA ISN'T BAD.

VANILLA ISN'T BAD. のレスポンシブな紹介サイトです。空と短い哲学から、一つにつながった店とアプリの棚へ進む構成です。

今後の更新の基準は [デザインの基本ルール（仮）](./DESIGN_RULES.md) にまとめています。文字サイズ・余白・棚の形に加え、店から選択、詳細へ進む順序と動きを記録しています。

## GitHub Pages

GitHubリポジトリ: https://github.com/yumi-ai-lab/vanilla-isnt-bad

公開先: https://yumi-ai-lab.github.io/vanilla-isnt-bad/?lang=ja

main ブランチを更新すると、GitHub Actions が構文チェック・テスト・ビルドを実行し、成功した場合に dist/ を GitHub Pages に公開します。プルリクエストではチェックだけを実行します。実行状況はリポジトリの Actions タブで確認できます。

GitHub Pages 上のサイトは、PCを起動していなくても、別のWi-Fiや携帯回線から確認できます。ローカルで編集しただけでは公開サイトは変わりません。変更をコミットし、GitHubへpushしてmainに反映する必要があります。

新しいリポジトリに再設置する場合は、Settings → Pages → Build and deployment → Source を GitHub Actions に設定してください。ワークフローは .github/workflows/pages.yml です。独自ドメインは設定していません。

## 起動

Node.js 22 以降で、次を実行してください。外部パッケージのインストールは不要です。

    npm start

http://127.0.0.1:4173 を開きます。別のポートを使う場合:

    npm start -- --port 4174

英語版は ?lang=en、日本語版は ?lang=ja で表示できます。画面右上の EN / JA ボタンでも切り替えられます。

## スマホで確認する

スマホとこのPCを同じWi-Fiにつなぎ、次を実行します。

    npm run preview:phone

表示された「Phone preview」のURLをスマホのSafariまたはChromeで開きます。127.0.0.1 や localhost は、URLを開いている端末自身を指すため、スマホからPCを見るためには使えません。

確認中はPCを起動したままにし、スリープさせないでください。ターミナルで起動した場合は、ターミナルも開いたままにします。Ctrl+Cで終了します。別のWi-Fiや携帯回線からはアクセスできません。ゲストWi-Fiで端末同士の通信が禁止されている場合は、通常の同じWi-Fiに接続してください。

複数のネットワークが検出された場合は、表示された候補からWi-FiのIPv4を選びます。

    npm run preview:phone -- --host 192.168.x.x

スマホ用プレビューは、選択したLANアドレスで dist/ のサイトファイルだけを配信します。ファイアウォールやルーターの設定は変更しません。URLのIPアドレスは、Wi-Fi接続を変えた際などに変わることがあります。

## 現在の内容

- 空の短い哲学から、公園の小さなアイス屋の全景へ進みます。承認された構図をそのまま使い、丸い屋根・左右の端・短い足元まで収めます。
- 店はPC・スマホ共通の assets/storefront-complete-v5.png（1254×1254）。承認画像を加工せず保存し、幅100%・最大900pxで表示します。背景と地面の外縁だけCSSでなじませ、建物を切り取ったり縦横に引き伸ばしたりしません。
- コーン、カップ、スクープ、ソフトクリーム機、三つのトレー、社名、APPS看板は一枚の画像に含まれます。以前の別パーツによるロゴ・看板・ケースは重ねません。保存先・制作方法・最終プロンプトは [画像制作記録](./ASSET_NOTES.md) に記録しています。
- 画像内の Focus・Notes・Trip の札は構図確認用の固定英語です。スマホで読むため、画像直下にもアプリ名と用途をHTMLで三列に添えています。この補足は日英切替・読み上げに対応します。現在は表示確認用の仮名で、実際のアプリ登録やリンクはありません。
- 実アプリを content.js に登録すると、補足の三列を従来の横スクロールできる棚へ切り替えます。詳細ダイアログと日英切替も維持しています。画像内の固定サンプルは登録内容と連動しないため、本番データを入れる段階で画像側の札と役割を整理してください。
- 実アプリの棚は、ネイティブのスワイプ、横スクロール、マウスのドラッグ、左右ボタン、矢印キー・Home・Endに対応します。長い名前・用途は詳細で全文を表示し、言語を切り替えても棚の位置を保ちます。無限ループや自動再生、縦ホイールの横変換はありません。
- 温かい白 #F7F3ED、ミルク色 #FCF9F4、墨色 #282826、淡いバニラ色 #E9DDB8。英字は Inter、日本語は Noto Sans JP をサイト内から配信します。本文400、冒頭とアプリ名500、社名600が基準です。文字に影は付けません。
- 冒頭は両言語で「Good as it is.」「Yours if you want.」。日本語版だけ「足さなくてもいい。」「だけど、足してもいい。」を添えます。共通の英語は index.html、各言語の原稿は content.js で変更できます。
- 目に見えるAPPSは画像内の吊り看板一つ。その位置に通常のHTMLリンクを重ね、補足へ進めるようにしています。冒頭の「アプリを見る」は、まず店全体へ案内します。
- 公園は承認画像に含まれます。以前の独立した背景画像は重ねません。空からクリーム色への穏やかな変化は維持しています。
- 冒頭は下から浮かび、ぼけが晴れるように登場します。注文窓に薄い二枚のガラスを重ね、左右へ1.6秒で開きます。側面の固定ガラス・枠・受け渡し台は画像内にあり、動きません。
- 店内の追加光は通常8%、ホバー・フォーカス時18%、タッチ端末では10%。棚内の冷気も薄く重ね、画像本来の自然光と質感を保ちます。
- 冒頭は60%、窓は65%が見え、スクロールが落ち着いてから再生します。字体と画像の準備を待ち、非表示タブでは再生を消費しません。見える割合が3%未満になると再生準備へ戻ります。
- ケース内の冷気は12秒周期。画面外・タブ非表示では停止し、動きなしでは消えます。足元には追加の煙を重ねません。
- 下段の日本語見出しは「まず、使い心地を」「味わってみてください。」。会社紹介は左から穏やかに登場し、スクロール検出が失敗しても隠れません。
- アプリ詳細はネイティブのダイアログ。Escape、閉じるボタン、外側のクリックで閉じ、選んだアプリへフォーカスを戻します。端末とサイトの動き軽減設定では、棚を即座に移動し、文字や窓の動きも止めます。

## アプリを追加する

content.js の apps 配列に、実際のアプリだけを追加してください。アイコンを assets/apps/ に保存し、以下の形で登録します。

    {
      id: "your-app",
      name: { en: "App name", ja: "アプリ名" },
      tagline: { en: "What it does, in one line.", ja: "用途を一言で。" },
      description: { en: "A short description.", ja: "短い説明文。" },
      icon: "./assets/apps/your-app.png",
      url: "https://your-actual-app-url.example",
      platforms: ["iOS", "Android"]
    }

url は実際の公開URLに置き換えてください。サンプルURLは説明専用です。詳細画面のアイコンを未指定にすると名前の頭文字を表示します。配列の順番で並び、登録数に合わせて横方向へ棚が延びます。PCとスマホで掲載するアプリは同じです。現在は全アプリに共通のバニラのケース画像を使います。

### 数が増えた場合の拡張方針

現在は全景の空気感を確認する三件のサンプルです。実アプリを登録した場合は全件を別の横一段の棚に表示し、6件でも12件でも店の画像の高さは変わりません。追加するのは content.js のアプリデータです。承認画像の固定サンプルを本番の棚とどう統合するかは、実データ投入時の次のデザイン工程です。

数が増えて一つずつ送る負担が大きくなったら、店頭には代表の6件程度を残し、「すべてのアプリ」から別一覧へ進む構成を推奨します。用途別の絞り込みや検索は、その一覧側に加えます。別一覧・検索・件数制限はまだ実装していません。ケースや文字を縮めて件数を詰め込まない方針です。

## 確認とビルド

    npm run check
    npm test
    npm run build

dist/ に静的配信に使えるファイルが出力されます。GitHub Pagesでも同じビルドを使用します。

公開ビルドはCSS・JavaScriptとそのデータモジュールの内容からバージョンを計算し、読み込みURLに付けます。CSSやアプリデータの変更時に古いファイルが再利用される問題を防ぎ、変更がないファイルのURLは維持します。

横棚はアプリ内ブラウザーの320・390・1280px幅で確認しています。矢印ボタン、ドラッグ、Home / End、末尾で停止する動作、ページの横はみ出し、日英切替時の位置保持を検証しました。ローカルの12件の仮アプリで、ドラッグによる誤起動がないこと、詳細の開閉とフォーカス復帰、動きなしでの即時移動も確認しています。仮データは公開していません。実機のiOS Safariやタッチ操作の確認とは区別しています。

自動テストでは、棚の末尾が区画幅の整数倍にならない場合、PCで複数のケースが見える場合、0件・1件・レイアウト未確定時の移動範囲を検証しています。既存の言語・URL・配信・キャッシュ更新のテストも実行します。

全景のv5はアプリ内ブラウザーの320・390・700・1280px幅で、画像全体の収まりと補足の文字のはみ出しを確認しています。390px・1280pxでは画面を見て構図を確認し、看板と冒頭のリンク、日英切替、動きの停止も検証しました。上記の横棚の操作検証は既存の登録済みアプリ表示についての記録で、現在の三件のサンプルは非操作の補足です。

## 画像

店舗全景は assets/storefront-complete-v5.png（1254×1254）。ユーザーが承認した output/imagegen/storefront-distance-study-v1.png と同じPNGです。CSSで縮小し、社名・看板・店内・ケースを同じ視点と光のまま表示します。旧画像は参照として保持しています。制作方法・最終プロンプトは [画像制作記録](./ASSET_NOTES.md) にまとめています。

棚は assets/vanilla-counter-interior.png（1586×992）を再使用します。7:4の枠に幅112%で表示し、重複する写真内の側面金具を減らしています。共通の銀の上下レール、下側66%のみの3pxの仕切り、透明なガラス札はHTML/CSSで作っています。過去のケース画像は比較用に保持しています。

屋台を差し替える場合は、注文窓の位置、カウンターへの接続、社名と看板も合わせて確認します。ローカルの参考画像 assets/art-direction.png と assets/*.prompt.txt は配信から除外しています。採用画像の生成条件は ASSET_NOTES.md に記録しています。

## 書体

assets/fonts/ に Fontsource Variable 5.3.0 配布の Inter と Noto Sans JP の通常体を、WOFF2 のまま同梱しています。サイト閲覧時に外部のフォント配信サービスへ接続しません。文字範囲ごとに分割したファイルを使用するため、表示する文字に必要なファイルだけが読み込まれます。英字の基本ファイルは先読みします。

読み込み中や通信失敗時は代替書体で文字を表示します。読み込み後は同じフォントデータを使いますが、OSごとの文字描画の差は残ります。日本語・英字とも配布元の文字範囲を保持しているため、現在の原稿だけに限定したフォントではありません。

配布元とバージョンは assets/fonts/sources.json、同梱ライセンスは assets/fonts/LICENSE-inter.txt と assets/fonts/LICENSE-noto-sans-jp.txt に記録しています。フォントのバイナリは変更していません。

原作者の資料: [Inter](https://github.com/rsms/inter)、[Noto CJK](https://github.com/notofonts/noto-cjk)。

### ロゴの再生成

`assets/wordmark-display.svg` と `assets/wordmark-small.svg` は同梱の Inter から生成したアウトラインです。ブラウザーでフォントを待たずに同じ形を表示します。元のフォントファイルは変更していません。

任意のデザイン作業として `scripts/build-wordmark.py` を実行すると再生成できます。Python、fonttools 4.65.0、brotli 1.2.0、Pillow を使用します。通常のNode.jsによるビルドと公開にはPythonや追加パッケージは不要です。使用した軸、文字間、個別の補正値はスクリプトに保存しています。
