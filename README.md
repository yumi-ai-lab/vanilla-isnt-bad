# VANILLA ISN'T BAD.

VANILLA ISN'T BAD. のレスポンシブな紹介サイトです。空と短い哲学から、一つにつながった店とアプリの棚へ進む構成です。

今後の更新の基準は [デザインの基本ルール（仮）](./DESIGN_RULES.md) にまとめています。文字サイズ・余白・棚の形に加え、店から選択、詳細へ進む順序と動きを記録しています。

## GitHub Pages

GitHubリポジトリ: https://github.com/yumi-ai-lab/vanilla-isnt-bad

公開先: https://yumi-ai-lab.github.io/vanilla-isnt-bad/?lang=ja

main ブランチを更新すると、GitHub Actions が構文チェック・テスト・ビルドを実行し、成功した場合に dist/ を GitHub Pages に公開します。プルリクエストではチェックだけを実行します。実行状況はリポジトリの Actions タブで確認できます。

GitHub Pages 上のサイトは、PCを起動していなくても、別のWi-Fiや携帯回線から確認できます。ローカルで編集しただけでは公開サイトは変わりません。変更をコミットし、GitHubへpushしてmainに反映する必要があります。

新しいリポジトリに再設置する場合は、Settings → Pages → Build and deployment → Source を GitHub Actions に設定してください。ワークフローは .github/workflows/pages.yml です。独自ドメインは設定していません。

## 起動

Node.js 22 以降で、次を実行してください。外部パッケージのインストールは不要です。

    npm start

http://127.0.0.1:4173 を開きます。別のポートを使う場合:

    npm start -- --port 4174

英語版は ?lang=en、日本語版は ?lang=ja で表示できます。画面右上の EN / JA ボタンでも切り替えられます。

## スマホで確認する

スマホとこのPCを同じWi-Fiにつなぎ、次を実行します。

    npm run preview:phone

表示された「Phone preview」のURLをスマホのSafariまたはChromeで開きます。127.0.0.1 や localhost は、URLを開いている端末自身を指すため、スマホからPCを見るためには使えません。

確認中はPCを起動したままにし、スリープさせないでください。ターミナルで起動した場合は、ターミナルも開いたままにします。Ctrl+Cで終了します。別のWi-Fiや携帯回線からはアクセスできません。ゲストWi-Fiで端末同士の通信が禁止されている場合は、通常の同じWi-Fiに接続してください。

複数のネットワークが検出された場合は、表示された候補からWi-FiのIPv4を選びます。

    npm run preview:phone -- --host 192.168.x.x

スマホ用プレビューは、選択したLANアドレスで dist/ のサイトファイルだけを配信します。ファイアウォールやルーターの設定は変更しません。URLのIPアドレスは、Wi-Fi接続を変えた際などに変わることがあります。

## 現在の内容

- ケースは自然光版 `assets/vanilla-tray-daylight.png` を使用しています。黒いゴム状の縁を細い銀の継ぎ目にし、照明の黄みを抑えました。店の周囲にはPC用 `assets/park-atmosphere.png` とスマホ用 `assets/park-atmosphere-mobile.png` を使い、緑が画面外に切れない構図にしています。左右の緑を保ち、画像の端だけ自然になじませています。背景の大きさは画面幅から決まり、棚が増えても引き伸ばされません。窓は閉じた状態でも店内が透け、開く途中も同じ透明度で移動します。画像の保存先・生成方法・最終プロンプトは [画像制作記録](./ASSET_NOTES.md) にまとめています。
- ケースに透明なHTMLのガラス札を重ねています。画像は5:4の比率で、確認用の6枠はPC・スマホとも同じ順番です。札はケース内の手前に収め、透ける面・細い反射・下端の厚みと小さな接地影で表現しています。背景のぼかしは1pxに抑えています。Focus・Notes・Trip・Tasks・Budget・Journalは表示確認用の仮名で、実際のアプリ登録やリンクはありません。用途の一行は `content.js` の `preview.*`、仮名と札の構造は `index.html` で変更します。札の文字は日英切替と読み上げに対応し、画像に焼き込んでいません。過去の陳列画像は別ファイルとして保持しています。
- 温かい白 #F7F3ED、ミルク色 #FCF9F4、墨色 #282826、淡いバニラ色 #E9DDB8。
- 屋台はマットな白い塗装と布の質感、控えめな銀の金具、柔らかい自然光で仕上げています。棚は別のケース画像を使い、厚みのある白い縁と銀の内枠を合わせています。
- 英字は Inter、日本語は Noto Sans JP をサイト内から配信します。本文400、冒頭とアプリ名500、社名600を基準にしています。会社紹介の日本語見出しは補足として400にしています。社名の文字間を調整したSVGを共通のロゴとして使い、小さな表示には別の光学補正を用意しています。
- 屋台の社名はマットな墨色の印刷をイメージし、屋根の明暗となじませています。APPS、空の見出し、本文は単色で輪郭の明瞭な文字です。文字の影は付けていません。
- 冒頭は両言語で「Good as it is.」を大きく、その下に「Yours if you want.」を16〜18pxで添えます。日本語版だけ「足さなくてもいい。」「だけど、足してもいい。」を14〜16pxの2行で添え、受け手が意味を拾える余白を残します。会社紹介の説明文は15〜16px。ヘッダー・会社説明・フッターの左右の基準を揃え、棚は店の外形につなげています。
- 目に見える「APPS」は右の吊り看板一つにしています。棚の見出しは読み上げ用に残し、カウンターの下からすぐケースが並ぶ構成です。
- 下段の見出しは「まず、使い心地を」「味わってみてください。」の2行。スマホ22px、PCで最大26px、太さ400、標準の字間とし、本文の15〜16pxより大きく組んでいます。スマホでは本文との間を28px取り、本文中の空行と改行も保持します。
- 空と短い哲学、店とつながったアプリの棚、短い会社の考え。店の画像内にあった飾りのケースは表示せず、実際のアプリの棚だけをカウンター下に置いています。
- PCは3列、スマホは2列。アプリ名はスマホ14px・PC16px、用途は12px・13px。実登録したアプリもサンプルと同じケースとガラス札で表示し、押すと詳細画面を開きます。実登録の長い名前・用途は棚では省略し、詳細画面では全文を表示します。短い名前と用途の一行を用意すると棚で比較しやすくなります。
- 社名は文字の輪郭を保持したSVG。屋台の看板を主役にし、フッターに小さく残しています。ヘッダーは右揃えの操作だけに整理し、スマホはEN / JA、PCは一覧と会社紹介へのリンクも表示します。屋台の読み上げ用キャプションにも社名を含めています。
- 冒頭の言葉は下から18〜52px浮かび、ぼけが晴れるように登場します。英語の見出し、補足、日本語の順に短くずらし、約1.2秒で読みやすい状態に落ち着きます。
- 冒頭は60%、窓は65%が見え、スクロールが落ち着いてから再生します。文字と画像の準備も待ち、非表示のタブでは再生を消費しません。見えている割合が3%未満になれば再生準備へ戻し、画面端に窓が数ピクセル残っていても再入場の演出を妨げません。「空へ戻る」で冒頭を、ほぼ画面外になった店へ戻ると窓を再度確認できます。
- 店の窓は閉じた状態から240ms置き、左右のガラスが1.6秒で開きます。画像の窓に重ねた独立したガラスなので、建物全体は動きません。店内の追加照明は通常16%、ホバーとフォーカスで最大35%、タッチ端末28%に抑えています。
- 会社紹介の文章は画面に入ると24〜52px左から900msで登場します。スクロール検出が失敗しても隠れない作りです。棚から区切り線まではPC64px・スマホ48px、線から文章まではPC40px・スマホ32px、紹介の下側はPC64px・スマホ48pxです。
- 操作の反応120ms、リンクと詳細の変化240ms、看板420msに加え、文章と窓の演出には約1秒使っています。減速は `cubic-bezier(.22,.61,.36,1)`。看板は最初に見えたときだけ最大1.5度の小さな揺れ。
- 通常の縦スクロール。ナビと冒頭のリンクは中央から下線が伸び、冒頭の矢印は4px下がります。キーボードのフォーカスでも同じ反応を返します。
- ケース全体とガラス札へのホバー、実アプリのフォーカス・選択で、内側の光が240msで少し強くなります。確認用のサンプルも光に反応しますが、ボタンにはせず通常のカーソルを保ちます。アプリアイコンは詳細画面で表示します。
- 背景は参考HTMLの3番に合わせ、最初の60vhをスクロールする間に空色からクリーム色へ変わります。スクロールの固定やズームは行いません。
- 参考HTMLの7番から、ケース内の冷気（12秒周期）と足元の3層の冷気（15秒周期）を採用しています。画面外・タブ非表示では停止し、動きなしでは消えます。煙突の煙は追加していません。
- EN / JAを切り替えても店・棚・会社紹介が動かないよう、両言語に必要な文字の高さと幅を確保しています。切替後の文章だけ120msで不透明度65%から100%へ変化します。表示していない翻訳は読み上げからも除外しています。
- アプリ詳細は240msで開くネイティブのダイアログ。スマホは画面下端から開くパネルです。Escape、44pxの閉じるボタン、外側のクリックで閉じ、選んだアプリへスクロールを要求せずにフォーカスを戻します。
- キーボード操作、端末の動き軽減設定、フッターの動き切り替えに対応。動きなしでは疑似要素と文字切替を含む動きを止め、冷気も消します。
- アプリ未提供のため公開アプリは登録していません。偽のアプリやリンクは表示しません。
- 基本の使い心地を磨き、使う人が足すかどうかを選べる、という思想です。冒頭の言葉は短くし、店と空の棚を見ながら意味がつながる構成にしています。共通の英語2行は index.html、日本語の補足と各言語の説明文は content.js で変更できます。

## アプリを追加する

content.js の apps 配列に、実際のアプリだけを追加してください。アイコンを assets/apps/ に保存し、以下の形で登録します。

    {
      id: "your-app",
      name: { en: "App name", ja: "アプリ名" },
      tagline: { en: "What it does, in one line.", ja: "用途を一言で。" },
      description: { en: "A short description.", ja: "短い説明文。" },
      icon: "./assets/apps/your-app.png",
      url: "https://your-actual-app-url.example",
      platforms: ["iOS", "Android"]
    }

url は実際の公開URLに置き換えてください。サンプルURLは説明専用です。詳細画面のアイコンを未指定にすると名前の頭文字を表示します。配列の順番で並び、登録数に合わせて棚の段が増えます。PCとスマホで掲載するアプリは同じです。現在は全アプリに共通のバニラのケース画像を使います。

### 数が増えた場合の拡張方針

今の実装は登録データに応じた段の追加まで対応しています。12件の仮データで、日英切替、全件表示、同じガラス札、詳細画面の開閉とフォーカス復帰をローカル確認しています。仮データは公開していません。

当面は6件程度を今の棚で見せ、増えてもPC3列・スマホ2列を保ちます。9〜12件ほどになり店が縦に長く感じられる段階で、店先は代表6件と「すべてのアプリ」に整理し、全件は独立した一覧で探す構成を推奨します。これは次段階の案で、現在は件数制限や別一覧を実装していません。

一覧でもガラス札と画像の表現を引き継ぎますが、建物を無限に延ばす必要はありません。用途による絞り込みを先に検討し、検索は実際の件数や探しにくさに応じて追加します。名前・用途の文字を小さくして件数を詰め込むことは避けます。

## 確認とビルド

    npm run check
    npm test
    npm run build

dist/ に静的配信に使えるファイルが出力されます。GitHub Pagesでも同じビルドを使用します。

公開ビルドはCSS・JavaScriptとそのデータモジュールの内容からバージョンを計算し、読み込みURLに付けます。CSSやアプリデータの変更時に古いファイルが再利用される問題を防ぎ、変更がないファイルのURLは維持します。

採用版の動きはアプリ内ブラウザーで320・390・768・1280px幅を確認し、言語切替後の店・棚・会社紹介の位置、横はみ出し、キーボードのリンク反応、動きなしでの冷気停止を検証しています。ローカル専用の仮アプリで、実際のネイティブダイアログの開閉と選択元へのフォーカス復帰も確認しました。仮アプリと検証ツールは配信物に含めていません。実機のiOS Safariやタッチ操作の確認とは区別しています。

演出を強めた版では、冒頭の上昇とぼかし、左右の窓の移動、会社紹介の左からの移動をアニメーション途中と終了後のブラウザー表示で確認しました。空のケースの照明、キーボードでの店内照明、動きの途中で「なし」にすると文章が不透明・移動なしに戻ることも確認しています。

表示の整理では、スクロール検出が一度も通知されない条件でも会社紹介の内容が隠されず、日英を切り替えられることをDOM検証で確認しています。登場演出は実際の検出を受けてから有限時間のアニメーションを開始し、途中で動きなしにすると元の可視状態へ戻ります。

再生条件の修正では、非表示・準備前・一部分だけが見えた状態で再生を消費しないことと、再入場時の再生をDOM検証しています。アプリ内ブラウザーでも初回と「空へ戻る」後の再生回数、閉じた窓からの移動、棚の内側の光、背景の両端の色、足元の冷気を確認しています。

## 画像

assets/kiosk-warm.png は、ユーザーの参考画像にあるマットな白い器と柔らかな光をもとに、内蔵 image_gen で屋台の素材を整えた画像です。ケースの縁には白い厚みと丸みがあります。以前の画像は assets/kiosk.png と assets/kiosk-refined.png に残しています。実ファイルは不透明のマット背景です。HTMLのSVGクリップで輪郭を表示し、`viewBox="0 40 1309 680"` で元画像のy=720、カウンターまでを見せています。下の飾りのケースや元画像の脚は表示せず、その直下を実際のアプリ棚とCSSの足元につなげています。空や看板は独立して扱えます。透過PNGであるとは扱っていません。

下の棚の `.case-frame` は `assets/vanilla-tray-daylight.png` を背景に表示します。確認用と実登録で同じCSSを共有しています。棚の本体と足元は、屋台に写る本体と同じ幅83.116883%（1088 / 1309）に揃えています。屋台画像を変更する場合は、SVGの表示範囲・輪郭・ロゴと看板の位置、styles.cssの本体幅も確認してください。

ローカルの参考画像 assets/art-direction.png と生成時のプロンプトは、GitHubリポジトリと公開サイトの両方から除外しています。

## 書体

assets/fonts/ に Fontsource Variable 5.3.0 配布の Inter と Noto Sans JP の通常体を、WOFF2 のまま同梱しています。サイト閲覧時に外部のフォント配信サービスへ接続しません。文字範囲ごとに分割したファイルを使用するため、表示する文字に必要なファイルだけが読み込まれます。英字の基本ファイルは先読みします。

読み込み中や通信失敗時は代替書体で文字を表示します。読み込み後は同じフォントデータを使いますが、OSごとの文字描画の差は残ります。日本語・英字とも配布元の文字範囲を保持しているため、現在の原稿だけに限定したフォントではありません。

配布元とバージョンは assets/fonts/sources.json、同梱ライセンスは assets/fonts/LICENSE-inter.txt と assets/fonts/LICENSE-noto-sans-jp.txt に記録しています。フォントのバイナリは変更していません。

原作者の資料: [Inter](https://github.com/rsms/inter)、[Noto CJK](https://github.com/notofonts/noto-cjk)。

### ロゴの再生成

`assets/wordmark-display.svg` と `assets/wordmark-small.svg` は同梱の Inter から生成したアウトラインです。ブラウザーでフォントを待たずに同じ形を表示します。元のフォントファイルは変更していません。

任意のデザイン作業として `scripts/build-wordmark.py` を実行すると再生成できます。Python、fonttools 4.65.0、brotli 1.2.0、Pillow を使用します。通常のNode.jsによるビルドと公開にはPythonや追加パッケージは不要です。使用した軸、文字間、個別の補正値はスクリプトに保存しています。
